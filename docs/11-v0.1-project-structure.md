## Responsibility split

`packaging/runtime-manifest.txt` is the single allowlist for production runtime artifact contents.

`tools/build_release.py` builds `dist/vps-bootstrap-v0.1.3.tar.gz` and `dist/SHA256SUMS` from that allowlist. It verifies canonical project version from `versions.yml`, optional tag consistency, mandatory runtime paths, archive path safety, and absence of development files.

`bootstrap.sh` is the only fresh-Ubuntu entrypoint. It performs OS/root/apt checks, installs bootstrap packages, stages managed project files under `/opt/vps-bootstrap/releases/<release-id>`, creates `/opt/vps-bootstrap/releases/<release-id>/venv`, installs pinned Python dependencies inside the staged release, atomically switches `/opt/vps-bootstrap/current`, installs `/usr/local/bin/vps-bootstrap`, then delegates to Python.

After successful bootstrap, `/usr/local/bin/vps-bootstrap` must not depend on the original checkout path.

`app/cli.py` owns SSH-terminal UX and subcommands:

```bash
sudo vps-bootstrap
sudo vps-bootstrap preflight
sudo vps-bootstrap full
sudo vps-bootstrap resume
sudo vps-bootstrap state
```

`app/preflight.py` owns read-only checks and report formatting.

`app/state.py` owns the JSON state machine with `pending`, `running`, `done`, `failed`, `skipped`.

`app/resume.py` owns phase orchestration. A `done` phase is never trusted blindly; it is verified before skip.

`app/base_setup.py` owns safe foundation changes: runtime directories, non-secret config, log file, journald example, managed time synchronization, swap/SSH phase policy, and Ansible foundation verification.

`app/time_sync.py` owns v0.1.2 managed time synchronization. It preserves already-working time sync and uses chrony only as fallback when actual synchronization is absent.

`app/swap.py` owns v0.1.3 managed swap discovery, planning, `/swapfile` creation, `/etc/fstab` persistence, verification and rollback.

`app/ssh_hardening.py` owns v0.1.3 SSH discovery, configured/effective/actual verification, Ubuntu 24.04 `ssh.socket` handling, safe two-port migration and rollback.

`ansible/` is intentionally a skeleton in v0.1. Future OS/service mutations belong there after pinned dependencies and verification behavior are defined.

```text
/var/log/vps-bootstrap/vps-bootstrap.log
/opt/vps-bootstrap/current
/opt/vps-bootstrap/current/app/
/opt/vps-bootstrap/current/ansible/
/opt/vps-bootstrap/current/templates/
/opt/vps-bootstrap/current/versions.yml
/opt/vps-bootstrap/current/venv/
/opt/vps-bootstrap/releases/
/usr/local/bin/vps-bootstrap
```

The repository must not contain runtime config, secrets, logs, database files, or backups.

## Runtime artifact contents

Only these manifest entries are allowed:

```text
bootstrap.sh
requirements.txt
versions.yml
app/
ansible/
templates/
```

The runtime artifact must not contain `AGENTS.md`, `README.md`, `docs/`, `tests/`, `.git/`, `.github/`, `tools/`, caches, local state, logs, config, or secrets.

Symlinks are not supported in runtime artifact. File modes are fixed by packaging logic: directories `0755`, `bootstrap.sh` `0755`, all other regular runtime files `0644`.
