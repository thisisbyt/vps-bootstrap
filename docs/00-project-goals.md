# Цели проекта

## Что должен решать VPS Bootstrap

Проблема: VPS периодически приходится менять из-за переезда между хостингами, потери сервера, ошибок конфигурации или необходимости поднять новый экземпляр.

Ручная настройка приводит к:

- забытым шагам;
- отличиям между серверами;
- ошибкам в firewall;
- разным версиям компонентов;
- потере настроек;
- повторению одних и тех же диагностик;
- риску восстановить нерабочую старую конфигурацию.

Проект должен превращать подготовку нового VPS в воспроизводимый процесс.

## Целевой пользовательский сценарий

1. Хостер устанавливает Ubuntu.
2. Пользователь получает IP, root/sudo-доступ и пароль/SSH key.
3. Пользователь входит на VPS.
4. Выполняет одну bootstrap-команду.
5. Скрипт устанавливает минимально необходимые зависимости.
6. Запускается интерактивный мастер.
7. Мастер задаёт вопросы только о данных, которые невозможно определить автоматически.
8. Пользователь выбирает требуемый профиль.
9. Установщик выполняет provisioning.
10. После каждого этапа выполняется проверка.
11. При ошибке состояние сохраняется.
12. После исправления причины можно выполнить resume.
13. В конце пользователь получает финальный отчёт и список предупреждений.

## Профили

Предусмотреть минимум:

- базовая подготовка VPS;
- Xray + 3x-ui;
- NaiveProxy;
- Xray + 3x-ui + NaiveProxy;
- мониторинг;
- полный стек;
- custom.

В дальнейшем могут появиться:

- российский exit node;
- reverse/relay server;
- backup node;
- другие proxy/VPN-протоколы.

## Что не должно требоваться от пользователя

Пользователь не должен вручную:

- ставить Python;
- ставить Ansible;
- создавать структуру каталогов;
- искать, какие пакеты нужны;
- вручную редактировать systemd unit;
- повторять десятки диагностических команд;
- помнить правильный порядок настройки UFW/SSH;
- помнить все прошлые ошибки и обходные решения.

Проект должен инкапсулировать накопленный опыт.
